# BEV感知低分：指标严格，模型也有真实缺陷

2026-10-15，针对已完成的ResNet50/FPN独立感知best进行CPU排查。
结论：**没有发现混淆矩阵或IoU公式算错；1m栅格的严格IoU会显著惩罚小行人的定位偏差，
但远距离行人的大面积漏检、近距离可见目标的失败和置信度排序问题都是真实存在的。**
不能把19.131%的全验证前景mIoU解释为“只因指标不合理”，也不能理解成“只看到了19%的人/车”。

当前融合/联合训练继续运行。本次没有修改正在运行的训练入口、模型、损失、配置或checkpoint，未启动额外GPU任务。

## 指标为什么会让分数低

这里评估的是三维标注框在ego BEV的二维投影分割，类别是background、vehicle、human。
矩阵行为真值、列为预测，IoU=TP/(TP+FP+FN)，前景mIoU只平均vehicle/human；背景没有混入前景平均。
新128条样本的混淆矩阵另用NumPy独立计数，与Torch逐项一致。

这不是nuScenes检测mAP。官方检测使用中心距离匹配、按类别设置范围，并过滤没有LiDAR/Radar点的GT；
当前实现对整个前75/后35/左右55m包络计算框投影IoU，未按官方检测的这些规则筛选。
参考：[官方检测定义](https://github.com/nutonomy/nuscenes-devkit/blob/master/python-sdk/nuscenes/eval/detection/README.md)。
本项目human还包括stroller等细类，vehicle包含多个车辆细类，不能与官方检测十类直接对应。

128条验证中，683个人类标注框有676个只占一个格子，比例**98.975%**。
单格目标的同类预测偏到相邻格后，严格IoU就是0，即使模型在其附近有响应。
将完整GT图当作完美预测、仅整体平移1m的解析对照：

| GT预测的变化 | vehicle IoU | human IoU |
| --- | ---: | ---: |
| 原位置 | 100% | 100% |
| 前移1m | 52.08% | 6.13% |
| 左移1m | 46.50% | 5.68% |

因此human IoU低不能直接换算成“漏掉了多少人”。栅格化下的严格定位、物体有无和目标数量是不同问题。
这些位移对照不代表真实预测具有统一1m偏移，也不提供对真实误差的因果分解。

## 放宽条件后，仍存在明显质量问题

### 按距离看，20m外行人接近失效

| 固定128条验证子集 | vehicle IoU | human IoU |
| --- | ---: | ---: |
| 0–20m | 48.55% | 17.55% |
| 20–40m | 24.82% | 0.91% |
| ≥40m | 5.67% | 0% |

仅看20–40m、标注可见度≥60%且至少有一个LiDAR/Radar点的131个人类框，
只有2个框覆盖到同类预测格，5个框中心的2m内存在同类预测格。
这是宽松的覆盖检查，未做实例一对一匹配、也未惩罚误报，**不是检测召回率**；即使这样仍很低。
对照0–20m同条件178个人类框：89个有框内同类格，131个中心2m内有同类格。
这说明近场已有一定能力，不能把整个距离范围概括成同一种失败。

### 允许定位偏差，并没有恢复大多数GT格子

| GT格子覆盖率：附近是否存在同类预测 | vehicle | human |
| --- | ---: | ---: |
| 必须同格 | 34.53% | 17.74% |
| 欧氏距离≤1m | 44.22% | 25.08% |
| 欧氏距离≤2m | 49.08% | 29.05% |

这里是以GT格子为分母的容差覆盖率，不是IoU，也不是按人/车计数。
相应2m容差精确率为83.99%/69.10%，提示不少预测靠近真实目标，但仍缺少大量目标处的预测。
仅以“都偏了一格”无法解释。

### 调阈值收益很小

用全部float32概率精确排序，合并相同分数，扫描同一子集的所有候选阈值；没有使用粗直方图截断低概率。
按类别独立二分类，这比实际三类互斥输出更宽松；最优值使用了该子集标签，只能看作诊断上限。

| 类别 | 原三类argmax IoU | 子集最有利二分类阈值下IoU | 阈值 |
| --- | ---: | ---: | ---: |
| vehicle | 25.11% | 26.30% | 0.09525 |
| human | 10.82% | 11.63% | 0.05799 |

human GT格子上的预测概率中位数仅约0.00000795。
问题不仅是输出阈值保守，当前特征/定位/监督形成的分数排序也存在缺陷。
不应在验证标签上选好阈值后把这个上限作为新的正式结果。

### 遮挡与不可观测GT会压低分，但不足以解释

将低可见度或没有传感器点的前景GT所在格设为忽略，并限于40m内，背景误报仍计入：
vehicle/human IoU为35.77%/12.13%，召回61.68%/28.90%。
它是自定义限制条件下的诊断，不是官方检测评估；尤其human仍然较差。
128条中vehicle/human几何采样覆盖率为99.932%/99.694%，多数目标投影不在采样视野外。
几何覆盖不能证明没有遮挡，也不能证明所有标定或动态曝光同步都正确。

## 已确认的实现限制，以及尚不能单独归因的部分

1. **视觉通路有效，但没有充分学好。** 固定前16个验证样本，正常图像前景mIoU 16.405%，
   图像置零0%，循环交换图像0.518%，仅保留位置查询/FFN/输出头0.360%。
   图像确实控制感知输出；这些干预是固定模型敏感性检查，不是驾驶因果收益证明。
2. **空间模块简化得比较重。** 当前32通道、只有一层空间交叉注意力，第一层查询只来自位置和可学习查询表。
   在同一几何下更换图像，实际测得全部采样offset、attention weights和view weights逐项完全不变，
   尽管最终BEV logits会改变。相机特征参与采样值，但没有第二层利用图像特征调整采样。
   相比之下，[官方BEVFormer-Tiny配置](https://github.com/fundamentalvision/BEVFormer/blob/master/projects/configs/bevformer/bevformer_tiny.py)
   是256通道、3层编码器、约800×450输入；任务和完整结构也不同，不能将其精度或训练轮数直接套用。
3. **预测深度没有直接约束空间采样。** 将实际深度logits全部置零，BEV logits保持逐项完全一致。
   深度损失仍通过共享主干间接训练图像特征；不能说深度监督没有梯度，也不能据此断言所有BEV都必须显式用深度。
4. **中远距人的输入特征较小。** 20–40m human最大相机投影框中位数为11.47×22.43像素，
   对应stride-8特征约1.43×2.80格；≥40m时中位数6.78×13.36像素。
   这是分辨率可能限制能力的证据，但近距离大目标也漏，分辨率不能解释全部问题。
5. **不只是独立验证泛化。** 64条固定训练样本的vehicle/human IoU为41.39%/14.56%，
   训练样本20–40m human IoU也仅2.92%。同时训练/验证之间存在差距。
   现有证据支持训练拟合与泛化均有问题，不能简单归结成“只需要再训几轮”或“只发生过拟合”。

这些是已确认的实现行为和性能现象。主干、分辨率、空间层数/通道数、损失与更新预算的各自贡献，
还需要独立训练对照，当前不能声称找到唯一根因。
相机相对LiDAR的时间差在该子集约−47.3至+1.9ms；已做自车位姿曝光补偿，但未在此次排查中验证全部动态目标同步。

## 后续应如何处理

保留现有全范围IoU、精确率和召回率，以便追踪旧结果；同时增加距离、可见度分层和1m/2m覆盖诊断。
若目标是评估检测能力，另外建立对象级输出和正式中心距离匹配，不能用格子召回冒充人数召回。
优先把“20–40m可见行人”列为感知改进的检查项；固定预算分别验证提高图像尺寸、增加空间交互层数/容量、
以及改善稀有小目标监督。单纯改阈值、只汇报近场或换一个更高分的指标都不足以解决当前问题。
