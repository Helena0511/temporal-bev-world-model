# BEV感知质量排查

新增2026-10-15指标/真实漏检专项排查见[BEV_METRIC_AUDIT.md](BEV_METRIC_AUDIT.md)。
已在CPU固定128个独立验证场景、64个训练场景检查指标、距离、可见性、容差、精确概率阈值及真实图像。
确认1m栅格会显著惩罚单格行人的偏移，但放宽到2m后human GT格子覆盖仍仅29.05%，
20–40m可见且有传感器点的131个人类框仅5个中心2m内有同类预测；新ResNet50仍存在真实感知缺陷。
这些子集诊断不能替代完整4,819条验证指标，整个排查未修改正在进行的融合/联合训练。

结论：当前简化感知实现与训练目标存在明显短板。现有证据不支持把低分直接归因于BEV表示失效，
也没有排除所有几何/遮挡问题。先前在感知指标很低时推进融合，只验证了流程，没有守住感知质量门槛。

## 已确认的配置差异

当前旧模型并非BEVFormer移植：图像主干仅三层随机初始化卷积，14,496个参数；
可训练感知参数441,999个，其中394,272个是逐BEV单元查询。只有一层空间交叉注意力，32通道，
单训图像128×352，BEV为1m栅格。原始1600×900图像被直接非等比缩放，内参虽同步缩放，视觉外形仍被压扁。
深度头只提供辅助监督，预测深度没有直接参与BEV采样权重；图中有沿相机射线延伸的前景预测，
与深度定位不足的表现一致，但该观察不能唯一定位原因。

[官方BEVFormer-Tiny配置](https://github.com/fundamentalvision/BEVFormer/blob/master/projects/configs/bevformer/bevformer_tiny.py)
使用预训练ResNet-50、256通道、三层时空编码、约800×450输入及检测头。
本项目的框投影分割IoU也不能直接与其nuScenes检测mAP对比。

## 固定验证子集的图像干预

从4,819条官方独立场景的城市工况验证序列中按索引等距取32条；不训练或调参。
采样规则、token和分场景数据保存在 `runs/city_phase1/perception_audit_v1/audit.json`。

| 同一checkpoint输入 | 前景mIoU |
| --- | ---: |
| 正常图像 | 3.836% |
| 归一化图像置零 | 0.492% |
| 批内交换整组图像，保留原几何 | 1.433% |
| 空间注意力的图像更新置零，仅保留位置查询/FFN/输出头 | 0.172% |

图像确实影响感知输出，不能称为视觉通路断开。交换图像为分布外敏感性测试，不是驾驶因果收益证明。
这个32条子集的mIoU不能替代全4,819条的3.279%。

真实vehicle格子5,729个，模型预测50,949个；真实human格子147个，模型预测48,824个。
human栅格召回约61.9%，精确率约0.186%，说明主要问题之一是大面积误报；这不是按人数计算的检测召回。
0–20m内的前景mIoU也仅6.218%，问题并非只发生在远处。

vehicle标注格子5,722/5,729、human 147/147有至少一个图像采样覆盖。
这只是投影/采样范围检查，不表示目标没有被遮挡，也不验证全部标注与曝光同步。
新增解析测试用有已知数值的像素网格检查相机、通道分头、层级和采样坐标，测试通过。
示例图为 `runs/city_phase1/perception_audit_v1/examples.png`，显示三条确定规则选出的样本。

## 训练目标的对照

旧损失分别计算背景、车辆、行人的平均CE，再对类别等权平均，等效于对稀有类别逐格施加很大权重。
解析常数预测测试确认：即使类别频率悬殊，均匀类别概率仍是该损失下的常数预测最优点。
这会影响概率校准和误报/漏报取舍，但不能据此认定它是全部误差的唯一原因。

新增可选`ce_dice`：按有效格子平均的CE，加前景soft Dice。历史默认`balanced`保留，所有新试验显式指定损失。
固定8个训练场景（含human标注），相同初始感知checkpoint、数据顺序、batch 2、200次更新：

| 模型/目标 | 训练前景mIoU | 训练vehicle IoU | 训练human IoU |
| --- | ---: | ---: | ---: |
| 旧Tiny + 类别等权CE | 21.898% | 34.749% | 9.046% |
| 同一Tiny + CE/Dice | 49.252% | 57.433% | 41.071% |
| ResNet50/FPN + CE/Dice，128×352 | 57.192% | 66.170% | 48.214% |
| ResNet50/FPN + CE/Dice，256×448 | 56.226% | 67.453% | 45.000% |

**这里全部是固定训练集的拟合指标，不是验证精度。** 新主干使用相同的非图像分支初始化，
图像主干来自ImageNet，FPN新初始化；主干学习率为其他参数的0.1，BN、stem和layer1固定。
CE/Dice在200步时减少误报，但human栅格召回从原损失的100%降为41.8%；
IoU的改善不能代替召回检查，新主训练日志也将同时记录精确率和召回率。
256×448方案同时改变分辨率和宽高比，不能把效果唯一归因于其中一项；200步下也没有优于低分辨率ResNet。
原始记录：`runs/city_phase1/perception_fit_tiny_v1/results.json` 与
`runs/city_phase1/perception_fit_resnet_v1/results.json`。

## 已实现的候选修正

- `resworld/image_backbone.py`：原生PyTorch ResNet-50/FPN，读取官方ImageNet参数，不依赖torchvision编译扩展。
- `resworld/perception_objectives.py`：可选CE/Dice及历史类别等权CE。
- `configs/bev_attention_city60_resnet50.json`：保持前75/后35/左右55m米制范围和1m栅格，替换图像主干。
- `scripts/train_staged_driving.py`：验证预训练文件SHA256、固定BN、区分主干学习率，CUDA仍要求仅一张可见卡。
  历史checkpoint缺少新字段时按显式默认值规范化，真实模型配置不同仍拒绝直接迁移。

官方权重来源为[PyTorch ResNet50 V2](https://download.pytorch.org/models/resnet50-11ad3fa6.pth)，
SHA256为`11ad3fa62ca79e40addfd354a8ec4b7c75143b3038b8d2a807fbc68deab379ca`。
已实际严格加载全部非分类层参数，源权重保存在 `weights/resnet50-11ad3fa6.pth`。
配置差异和预训练数据的差异意味着这仍是改进变体，不是等预算的原版BEVFormer复现。

当前54项测试通过，包括已知像素采样、稀有类别常数预测梯度、未知区域掩码、ResNet输出步长、BN固定、
联合阶段冻结规则以及旧数据/几何/规划测试。

## 完整验证集结果与漏检问题

已核对新旧checkpoint的数据清单SHA256、官方划分SHA256、BEV几何及三类GT格子总数一致。
下表均为同一4,819条验证序列上的best：旧Tiny第3轮，新ResNet50第4轮。
可复查汇总为 `runs/city_phase1/perception_resnet50_comparison.json`。

| 栅格级指标 | 旧Tiny/类别等权CE | 新ResNet50/CE-Dice |
| --- | ---: | ---: |
| vehicle IoU | 6.349% | 26.222% |
| human IoU | 0.208% | 12.041% |
| 前景mIoU | 3.279% | 19.131% |
| vehicle精确率 | 6.562% | 49.283% |
| vehicle召回率 | 66.165% | 35.912% |
| human精确率 | 0.208% | 24.362% |
| human召回率 | 69.438% | 19.229% |

新模型的IoU及精确率明显改善，但召回率下降，尚不能认为感知已训练好。
human真实格子24,213个，新模型命中4,656个、漏掉19,557个，另有14,456个误报格子；
旧模型则有8,057,593个human误报格子。当前主要变化是从大面积误报转为更保守的预测，
仍需按距离、目标尺寸和遮挡检查漏检，并用验证精确率/召回率曲线区分类别阈值与特征定位问题。
这些统计按BEV格子计数，不是按车辆或行人人数计数。

四轮前景mIoU依次为11.923%、17.412%、18.754%、19.131%，最后一轮仍有小幅提升，
但不足以证明单纯延长训练能解决召回不足。新旧分别为11,240和5,620次更新，
同时改变了预训练、主干、损失与图像尺寸，因此不能把提升单独归因于某一项。
新模型量化稀疏深度MAE为3.364m；新旧图像分辨率及有效深度像素数不同，不能当作严格配对像素的深度对照。
新的ResNet50感知模型尚无融合/规划结果，历史联合规划ADE 0.9644m不属于这个新模型。

`runs/city_phase1/resnet50_staged_v2/status.json`；待两阶段完成后自动汇总验证对比。
