# BEV 范围的物理设计依据

> 当前阶段：常见城市驾驶，见 `docs/CITY_PHASE1.md`。城市版本参考停车视距70m，
> 推导前75m、后35m、左右55m；公路参考的前80m版本保留为历史候选。
> 程序分别输出城市与公路配置，训练脚本当前默认城市配置。

依据用户的修正：先明确目标道路和运动条件，再确定 BEV；数据集只检查覆盖、越界和域差异。
训练标签最大值不作为设计输入。此前的 `wide_*.json` / `bev_attention_full.json` 60m 范围保留为
数据覆盖实验候选，不作为正式道路设计结论。

## 标准能提供什么

道路标准给出车道、横断面、视距等设计指标，没有直接给神经网络规定一个 BEV 矩形。
需要区分国家标准 GB 与公路/城市道路行业标准 JTG、CJJ，以及适用道路等级。

- 公路参考：[交通运输部《公路工程技术标准》JTG B01-2014 公告](https://xxgk.mot.gov.cn/jigou/glj/202006/t20200623_3312197.html)，
  [部网站标准全文](https://xxgk.mot.gov.cn/2020/jigou/glj/202006/P020230628577830212881.pdf)。
  表4.0.2 的60km/h车道宽度为3.50m；表4.0.15 的60km/h停车视距为75m，80km/h为110m。
  这些是相应公路设计指标，不能直接说成自动驾驶感知必须覆盖的距离。
- 城市道路需要采用相应的城市道路标准体系，不能把公路指标直接当城市道路强制值。
  浙江自然资源部门公开的[城市道路工程论证资料](https://zrzyt.zj.gov.cn/module/download/downfile.jsp?classid=0&filename=a41ed183b99444258d2c9f4d1282de5e.pdf)
  给出60km/h城市主干路停车视距70m，并引用CJJ37-2012（2016年版）中≤60km/h混行车道3.50m、
  小客车专用车道3.25m。该资料用于说明道路类型差异，不据此代替完整现行规范的工程审查。
- nuScenes场景在波士顿、新加坡；中国标准只作为我们设定的目标道路参考，
  不用于断言这些场景道路符合中国规范，也不自动删除不符合候选运行条件的评估样本。

## 设计方法

前向候选范围：

`L_front = max(v_design * T_plan, S_stop_reference) + M_front`

实际部署还需考虑系统延迟、路面附着与坡度、交通信号/路口识别距离、遮挡与传感器有效距离。
道路设计停车视距是参考包络，不能替代这些系统验证。

侧向候选范围：

`L_side = max(从自车到道路远侧及路侧活动区的距离, 横向来车速度 * 冲突观察时间, 转弯包络) + M_side`

自车可能位于最外侧车道，不能把道路总宽简单除以二。交叉口还需观察横向来车，
所以车道宽度本身不足以确定左右范围。当前候选显式考虑横向来车；尚未对转弯包络单独建模。

后向候选范围：

`L_rear = rear_closing_speed * lane_change_time + M_rear`

后车接近速度、交互时长与裕量都是设计假设，标准没有统一规定BEV后向范围。

## 可审查的60km/h公路参考候选

`resworld/bev_design.py` 完全不读取数据集，输出：

| 输入 | 数值 | 来源性质 |
| --- | ---: | --- |
| 道路参考设计速度 | 60km/h | 当前研究假设，尚未被用户确认为最终运行范围 |
| 参考车道宽度 | 3.50m | JTG B01-2014表4.0.2 |
| 参考停车视距 | 75m | JTG B01-2014表4.0.15 |
| 预测时间 | 3s | 当前任务定义 |
| 双向机动车道总数 | 最多6条 | 研究假设 |
| 中分带/路侧活动区 | 3m / 5m | 研究假设 |
| 横向来车 | 60km/h、观察3s | 研究假设 |
| 后车最大接近速度/变道时长 | 10m/s、3s | 研究假设 |
| 前/侧/后裕量 | 各5m | 研究假设；不是国标规定的BEV裕量 |

由此得到：3s行驶距离50m，前向取max(50,75)+5=80m；道路远侧包络约27.25m，
横向来车3s可达50m，侧向取50+5=55m；后向10×3+5=35m。
候选范围为 **x∈[-35,80]m、y∈[-55,55]m**。采用1m端点栅格时为116×111，
实际分辨率为1m；若改0.5m则为231×221，计算量与显存都需要重新测量。
注意：这是可解释的研究候选，不是“符合国标所以可部署”的认证结论，也不是所有道路的通用范围。
如果目标包括80/120km/h道路，应独立扩展该设计包络。

生成与复核：

```bash
python -m resworld.bev_design
python -m scripts.analyze_bev_coverage --model-config configs/bev_attention_road60.json
```

`configs/bev_road60_design.json` 保存引用、假设和推导；`configs/bev_attention_road60.json` 是相应模型配置。
数据覆盖结果不回写上述设计参数。实际选择最终训练范围前，应明确目标道路、速度上限、交互场景与分辨率。
`scripts/train_full.sh` 默认使用此物理候选配置；可通过 `RESWORLD_MODEL_CONFIG` 指定其他明确设计的配置。
尚未启动正式训练，不能把该60km/h研究假设视为已确认的最终运行范围。

## 与BEVFormer思路的组合

新实现 `resworld/bev_attention.py` 借鉴[BEVFormer论文](https://arxiv.org/abs/2203.17270)的空间交叉注意力与时序注意力：
学习BEV查询将多高度参考点投影到六路相机，从两级图像特征采样；历史BEV先按位姿对齐，
再进行带可见性掩码的局部多头时序采样。时序搜索半径按米定义，避免栅格改变后物理范围变化。
实现采用分块的局部采样，不创建BEV查询数量平方的全局注意力矩阵。

场景分支使用时序融合特征；残差分支使用独立逐帧视觉BEV，在统一坐标系中相减，
不从已经时序平滑的场景特征中直接求差，也不把状态FiLM变化混入新分支的残差。
残差仍可能包含图像编码、遮挡、投影/插值误差，不能解释为纯物体运动。

这是BEVFormer-inspired候选，不是原版完整实现：仍是小卷积编码器，未接原版预训练ResNet/FPN，
没有原版检测/地图监督，空间与时序模块顺序、时序窗口和训练方案也有区别。
增强感知与残差预测可能互补；是否提高规划精度需要实测。

已有同范围消融配置（均保留为60m历史实验候选）：

- `wide_lift_splat.json`：lift/splat + 卷积融合 + 视觉残差。
- `wide_bev_spatial.json`：空间查询注意力 + 卷积融合 + 视觉残差。
- `wide_bev_temporal_no_world.json`：空间/时序注意力，关闭世界增量。
- `wide_bev_temporal.json`：空间/时序注意力 + 视觉残差世界增量。

比较前两项检验空间感知，比较第二/第四项检验时序融合，比较第三/第四项检验残差世界分支。
应在最终固定的物理范围、同一训练数据与预算下重新生成并训练这些对照。
原版lift/splat checkpoint保持兼容，旧模型75条验证轨迹指标已验证不变。
新模块通过投影、可见性、梯度、无效历史、米制搜索半径、视觉残差隔离等测试；
CPU的mini/trainval小批前向反向均通过。当前没有新架构正式训练的精度提升结论。

本轮验证记录：共33项测试通过。`runs/bev_attention_trainval_smoke/` 为真实trainval小批测试，
`runs/bev_attention_full_smoke/` 为较大60m历史候选，`runs/bev_road60_smoke/` 为新物理候选
（116×111、128×352图像、batch=1）的三次更新及抽样验证。均通过有限损失/梯度检查。
较大配置的世界/采样分支在最初几次更新中梯度仍很小，不能据此认为已经学到环境演化。
轻量空间/时序原型80步单条真实序列过拟合通过，规划损失4.5294→约0.2906，ADE约0.4186m，
记录在 `runs/bev_attention_overfit_final/`。此结果仅证明可优化，不是泛化精度。
