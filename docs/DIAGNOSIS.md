# 当前 checkpoint 的误差诊断

对象：`runs/mini_pipeline_check/best.pt`，mini 训练 1 epoch，独立验证集 75 条。
执行：`python -m scripts.diagnose_driving`。完整数值：`runs/mini_diagnosis.json`。
这些是同一 checkpoint 的推理敏感性测试；各模块的因果收益必须通过独立重训对照确认。

| 推理条件 | ADE（米） |
| --- | ---: |
| 完整模型 | 3.7629 |
| 图像置零（归一化后的零值） | 3.7227 |
| 历史运动状态置零 | 9.1405 |
| 世界模型输出的 BEV 增量置零 | 3.7838 |
| 使用初始轨迹，去掉最终修正 | 3.7893 |
| 过去位姿计算的匀速基线 | 1.9571 |

图像置零时预测点平均移动 0.194 米，运动状态置零时移动 8.472 米。
当前模型强烈依赖运动状态；视觉信息尚无清晰的验证收益。不能把这个结果解释为图像在任务中无用。
世界模型增量置零会让预测移动约 1.215 米，但最终 ADE 几乎不变；说明它会影响输出，
尚未证明这些影响稳定改善误差。

误差按轴分解：纵向平均绝对误差 3.277 米，横向 1.459 米；匀速基线分别 1.392、0.850 米。
两轴误差不能相加后等同于 ADE。当前不是只有纵向速度估计问题，横向也需要改善。

几何覆盖：当前 BEV 前向范围仅 [-15,15] 米。14.52% 的初始轨迹参考点、13.81% 的有效 GT 点
超出 BEV。验证集有效 GT 前向位置最大 26.39 米，95% 分位 19.71 米。
FGTR 对越界参考使用 border padding，因而缺少对应轨迹位置的局部特征。
应先核对与原版的轴约定，再按 trainval 训练集的轨迹分布确定覆盖范围，并保持足够的栅格分辨率。
范围变化后必须重训，不能把原 checkpoint 换范围后的结果当作可比较精度。

样本覆盖：mini 训练左/直/右计数为 22/277/0，验证为 3/55/17。
保持官方场景隔离，改用有右转训练样本的 trainval 数据；不能混入验证场景。

下一步按以下顺序推进，单项修改留独立日志与权重：

1. 几何与标签：核对真实 LiDAR 投影、米制坐标、逐步位移/累计位置、时间间隔与 BEV 覆盖。
   当前已有解析几何和掩码测试；真实投影叠图仍应作为进一步感知检查。
2. 数据与收敛：建立包含左/直/右的 trainval 小规模、场景隔离训练/验证集，做多样本过拟合和
   持续训练曲线，避免用单 epoch 与缺失类别的 mini 判断算法上限。
3. 感知：验证深度预测与投影，随后优先考虑预训练编码器与图像分辨率。
   判断标准为视觉输入是否改善独立验证误差，而非仅看梯度非零。
4. 运动基线：保留匀速；可以单独尝试“运动学先验 + 学习修正”的变体，
   但必须标明它改变了模型，不与原版复现混为一谈。
5. 世界模型与 FGTR：在前述基础稳定后，对相同数据/训练预算分别重训无世界分支、无 FGTR
   和完整模型，按场景、导航指令、纵/横向误差比较。现在没有证据支持单纯加深这些模块。

阶段门槛是先稳定超过匀速基线，再比较各模块收益；这不是可部署或行车安全的验收标准。
