# 第一阶段：常见城市驾驶

本阶段以城市道路、0–60km/h、3秒规划为研究目标，先覆盖直行、左右转和停车/低速至正常行驶。
跟车、行人/非机动车、路口交互是后续评估目标；当前没有这些交互的独立真值标签，
不声称已完成逐场景能力验证。高速、泊车、极端天气暂不作为本阶段专项优化目标。
nuScenes已有夜间、雨天数据仍保留，不通过删除困难验证样本改善指标。

## BEV与感知

- 城市道路工程参考采用CJJ37-2012（2016年版）的60km/h混行车道3.50m、停车视距70m。
  参考来源与适用性见 `docs/BEV_DESIGN.md`；这是工程包络设计，不是标准规定的神经网络范围。
- 结合3秒预测、路口横向来车和前/侧/后裕量，候选范围为 **前75m、后35m、左右各55m**。
- 较大配置 `configs/bev_attention_city60.json`：0.5m栅格、221×221、64通道、两层空间注意力。
- 小试验 `configs/bev_attention_city60_pilot.json`：同米制范围，1m栅格、111×111、32通道、一层空间注意力。
  小试验用于检查数据和优化流程，不能把它的结果当作较大配置精度。
- 感知使用BEVFormer-inspired空间查询和局部时序注意力；时间残差保留独立逐帧视觉特征。
  仍使用小卷积图像编码器，尚未接入原版预训练ResNet/FPN。

## 小规模数据试验

`resworld/city_selection.py`从官方trainval训练/验证场景分别选择完整6步标签、过去速度≤60km/h的序列：

| 集合 | 序列数 | 场景数 | 左/直/右 |
| --- | ---: | ---: | --- |
| 训练 | 48 | 48 | 16/16/16 |
| 验证 | 24 | 24 | 8/8/8 |

训练、验证场景无重叠。选择过程先轮换场景，再取更多同场景窗口，固定seed保证可复跑。
序列token、速度和场景保存在 `runs/city_phase1/selection.json`。
该选择只用速度近似限制工况，没有地图道路等级标注，不能把它称为经过验证的完整城市ODD。
路线均衡的24条验证结果也不代表官方5,569条验证序列的总体精度。

当前选中训练过去速度为0–57.30km/h，验证为1.49–38.85km/h。天气未作筛除。
描述文本中训练8个场景提及night、6个提及rain，验证分别6和5；仅为文本线索，
不是气象真值标签。可审阅 `runs/city_phase1/scenario_notes.json` 中的原始场景描述。

## 当前实验与后续顺序

CPU小试验：48条训练序列、2 epochs、batch size 2、64×160图片、32通道、1m栅格。
这是训练流程验证，不是正式收敛实验。日志、配置与checkpoint位于 `runs/city_phase1/pilot_train/`。
评估同时记录ADE、1/2/3秒误差、纵向与横向平均绝对误差，并按指令、速度、场景分组，
保留仅用过去位姿计算的匀速基线。

本次2轮CPU试验已完成，共48次优化更新。该24条均衡验证序列上：

| 指标（米） | 第一轮 | 第二轮 | 匀速基线 |
| --- | ---: | ---: | ---: |
| ADE | 3.5620 | 2.6349 | 1.8863 |
| 纵向平均绝对误差 | 3.3564 | 2.5114 | 1.3400 |
| 横向平均绝对误差 | 0.6283 | 0.4247 | 1.0133 |
| 3秒终点误差 | 6.2801 | 4.7240 | 4.0099 |

模型在这批数据的横向指标较好，整体ADE仍弱于匀速，主要差距在纵向。
样本少、训练短，而且导航来自未来轨迹的离线oracle标签；不能据此认定感知架构或残差分支带来稳定收益。
本次数据与旧mini的75条验证不同，不能把2.6349与旧mini的3.7629直接比较。
本轮37项单元测试通过，包含样本选择不跨split、路线平衡与场景多样性、城市/公路参考值区分。

后续精度排查：见 `docs/ACCURACY_STATUS.md`。同数据/预算的运动学先验独立变体达到ADE 1.6096m，
但横向误差从0.4247变为0.6382m，仍需扩大验证。原城市模型与该变体分别保存，未覆盖原结果。
感知与自车状态的独立训练、输入隔离定义和分阶段融合试验见 `docs/CAUSALITY_TRAINING.md`。

```bash
python -m resworld.bev_design
python -m scripts.select_city_data
python -m scripts.train_driving --version v1.0-trainval --mode train \
  --model-config configs/bev_attention_city60_pilot.json \
  --selection-file runs/city_phase1/selection.json \
  --epochs 2 --batch-size 2 --image-height 64 --image-width 160 \
  --output runs/city_phase1/pilot_repeat
```

选择清单SHA256会写入配置与checkpoint。恢复训练/评估检查清单内容，防止同一路径被替换后混淆样本。
加载试验checkpoint时，提供同一version、图像尺寸和selection-file；额外传 `--full-validation`
可评估完整官方验证集，而不是均衡小试验集。

接下来应扩大场景隔离的城市优先训练集，观察收敛和匀速基线差距；在同一物理范围和数据预算下
比较空间注意力、时序注意力与残差世界分支。若视觉输入仍无收益，优先检查投影/深度并接入预训练感知，
不直接启动未经验证的长期大配置训练。

`scripts/train_full.sh`现默认城市0.5m配置、trainval、12 epochs，尚未启动长训练。
初期会话的普通Python入口CUDA不可用，后续已通过conda入口验证单卡CUDA并启动感知单训，
单卡约束、运行状态见 `docs/CAUSALITY_TRAINING.md`。CPU小试验不能代替正式大配置训练和显存验证。

正式阶段的数据清单也已准备：`runs/city_phase1/full_selection.json` 保留所有满足上述速度与完整未来标签
条件的22,480条训练序列、4,819条验证序列，分别来自699和150个官方场景，无场景交叉。
训练左/直/右为1,241/19,669/1,570，验证为240/4,241/338，保留自然路线分布并分组报告。
这仍是工况筛选集，速度条件不能证明道路等级。`scripts/train_full.sh`默认读取该清单，
避免城市阶段误用未经筛选的全部序列；如果清单不存在会先生成。
